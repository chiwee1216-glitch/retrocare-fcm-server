# Google 式天氣頁與快速登入設計

## 目標

病人端與看護端首頁都移除原本的天氣卡片，在通知鈴鐺左側新增天氣圖示按鈕。按下後開啟完整天氣頁，資訊排列接近使用者提供的 Google 天氣參考圖，同時改善登入後等待過久的問題。

## 首頁入口

### 病人端

- AppBar 右側依序顯示天氣按鈕、通知鈴鐺。
- 移除首頁 `WeatherCard`，讓服藥倒數成為首頁第一個主要內容。
- 天氣按鈕使用 Material 天氣圖示，tooltip 為「查看天氣」。

### 看護端

- `CaregiverHeader` 右側依序顯示天氣按鈕、通知鈴鐺。
- 兩個按鈕使用相同的 46 x 46 尺寸、陰影和視覺層級。
- 移除 `CaregiverWeatherStrip`。

病人端與看護端共用同一個 `WeatherPage`，避免兩套天氣 UI 與資料邏輯逐漸不一致。

## 天氣頁

### 視覺方向

參考 Google 天氣的資訊層級與排列，不直接複製品牌：

- 白色或極淺灰背景。
- 頂部顯示 GPS 地點、定位來源和更新時間。
- 大型目前溫度與清楚的天氣圖示。
- 同區顯示體感溫度、降雨機率、濕度、風速。
- 黃色作為溫度趨勢與目前選取狀態的強調色。
- 維持 App 既有藍色作為導航、按鈕和互動色。
- 面板邊角不超過 8px，避免與現有照護工具產生過度卡片化的落差。

### 資訊內容

1. 地點列
   - GPS 取得的座標或反向地理名稱。
   - 顯示「手機 GPS」或「預設位置」。
   - 定位失敗時顯示明確警告，不偽裝成真實所在地。

2. 即時天氣
   - 天氣圖示。
   - 目前溫度。
   - 天氣描述。
   - 體感溫度。
   - 降雨機率。
   - 相對濕度。
   - 風速。

3. 逐時預報
   - 顯示至少未來 12 小時。
   - 使用折線顯示溫度趨勢。
   - 每個時間點顯示時間、溫度、天氣圖示與降雨機率。
   - Flutter CustomPainter 僅用於資料折線，不製作裝飾插圖。

4. 七日預報
   - 顯示星期、天氣圖示、最高與最低溫、降雨機率。
   - 今日項目有輕量底色強調。

5. 更新控制
   - 支援下拉重新整理。
   - 顯示氣象資料更新時間。
   - 顯示定位與資料取得錯誤。

### 準確度與資料來源

- 使用手機高精度 GPS 座標。
- Open-Meteo request 加入：
  - current weather
  - hourly temperature、apparent temperature、weather code、precipitation probability、humidity、wind speed
  - daily weather code、最高／最低溫、降雨機率
- 時區固定使用 `Asia/Taipei`。
- 快取成功資料 30 分鐘，避免首頁或頁面重建時重複定位和呼叫 API。
- 使用者手動下拉時忽略快取並重新定位與查詢。
- 天氣不讀寫 Firestore，不消耗 Firestore 額度。

## 快速登入

### 已確認的延遲來源

目前登入流程在導航到首頁前依序等待：

- Firebase Auth。
- Firestore 使用者文件。
- ESP32 本機設定。
- Firestore 即時同步初始化。
- FCM Token 取得與後端重新綁定。
- 看護求助監聽。
- 啟動頁另外等待緊急聯絡人與固定延遲。

當 Firestore 額度、DNS、FCM 或 Render 回應較慢時，整個登入畫面會被其中一個非核心步驟阻塞。

### 新流程

前景只等待登入必要資料：

1. Firebase Auth 成功。
2. 讀取 `users/{uid}`，取得角色與基本資料。
3. 載入本機 ESP32 URL。
4. 立即導航至病人或看護首頁。

導航後背景啟動：

- Firestore medicines、tasks、devices、schedules 即時監聽。
- FCM Token 初始化與後端重新綁定。
- 緊急聯絡人載入。
- 看護求助監聽。

每項背景工作獨立捕捉錯誤，不得因其中一項失敗把使用者登出或送回登入頁。

### FCM 失敗恢復

- FCM 初始化不阻擋登入，但必須透過全域狀態顯示成功、連線中或失敗。
- 失敗時病人端與看護端首頁顯示「通知服務尚未連線，目前可能收不到背景服藥提醒」警告。
- 重試節奏：
  - 第一次失敗後立即重試一次。
  - 30 秒後重試。
  - 2 分鐘後重試。
  - App 回到前景或網路恢復時再次重試。
- 同一時間只能有一個初始化工作，避免重複註冊 Token。
- 成功後取消待執行的重試並自動隱藏警告。
- 警告提供「重新連接」按鈕，讓使用者手動觸發。
- 設定頁也提供「重新連接通知」入口並顯示最後錯誤。

### 啟動頁行為

- App 已有登入狀態時，同樣只等待角色文件，立即進首頁。
- 移除啟動時固定 500ms 延遲。
- 使用者文件讀取保留合理逾時與清楚錯誤。
- 首頁各區塊在資料尚未完成時顯示自身的載入或空狀態。
- FCM 或 Render 暫時失敗時記錄錯誤並稍後重試，不阻擋使用 App。

## 測試

### 天氣

- GPS 成功時使用手機座標並標示「手機 GPS」。
- 定位拒絕或逾時時使用預設位置並顯示警告。
- 快取 30 分鐘內不重複呼叫定位與天氣 API。
- 手動更新必須繞過快取。
- 小螢幕沒有文字重疊，逐時區可水平捲動。

### 登入

- Auth 與角色文件完成後即可導航，不等待 FCM。
- FCM 初始化失敗仍可進首頁。
- FCM 失敗時顯示警告並依節奏重試。
- FCM 成功後警告自動消失，且不重複註冊多個背景工作。
- 緊急聯絡人逾時仍可進首頁。
- 即時同步稍後成功時畫面自動更新。
- 未知角色和缺少使用者文件仍顯示明確錯誤。

### 回歸

- 病人與看護通知鈴鐺功能保持不變。
- 首頁不再自動請求天氣。
- 服藥、藥盒、通知與求助功能不因背景初始化改動而失效。
